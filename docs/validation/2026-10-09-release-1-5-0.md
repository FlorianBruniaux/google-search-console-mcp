The actual Trafilatura 2.3.1 environment passes all nine extraction tests. Documentation passes 6 tests, translations pass, Astro has zero diagnostics and builds 61 pages, and Chromium/macOS passes 111 browser tests. Updated homepage/documentation baselines reflect version 1.5.0; the source site was inspected before accepting them.

Correction to the initial local distribution-check claim: the first remote deployment failed two of 29 built-distribution checks because their homepage banner expected the literal v1.4.0. The failure was reproduced locally (27 passing, two failing), then fixed to assert the actual changelog version/date. All 29 checks pass with the test correction. This affects site validation only; the PyPI publish workflow passed 1,953 Python tests and published artifacts with separately verified matching hashes. Site deployment still requires a successful run on the corrected main commit.

The locally built 1.5.0 wheel installs outside the checkout and exposes 96 tools. An offline synthetic indexing-matrix CLI call keeps current indexing unknown, rendering unavailable and provider requests at zero. The base wheel does not install Trafilatura. This is an installed artifact check, not proof of a completed PyPI publication or live Google/Bing access. Remote release/deployment status must be verified independently.

The active app MCP returned a catalogue of 85 tools before publication. Updating a package on disk does not replace that running process or authenticate a native agent workflow. Client/server reload and the launcher-selected version remain separate checks. Native host dispatch, aggregate provider-attempt enforcement and expert accuracy remain outstanding in #38/#39/#6.
